1. SCOPE

These standards apply to all systems, code repositories, pipelines and
cloud resources operated by Lumenvale Technologies Inc.

2. SECRET STORAGE

2.1 All secrets (passwords, API keys, client secrets, certificates,
    connection strings) must be stored in Azure Key Vault. Secrets must
    never be stored in source code, notebooks, configuration files,
    pipeline variables or chat tools.
2.2 Databricks jobs read secrets from Key Vault-backed secret scopes.
    Databricks-backed secret scopes are not permitted in production.
2.3 Each workload has its own Key Vault per environment, named
    kv-<workload>-<env>-<region>-<instance>. Key Vaults have purge
    protection enabled and soft-delete retention of 90 days.

3. ROTATION REQUIREMENTS

  Credential type                          Maximum lifetime / rotation
  ---------------------------------------  ---------------------------
  Service principal client secrets         90 days
  Databricks personal access tokens (PAT)  30 days (non-production only)
  External partner API keys                180 days
  TLS certificates                         397 days (auto-renewed)
  Storage account shared keys              Disabled - not permitted

Prefer managed identities and OAuth machine-to-machine (M2M)
authentication over secrets wherever possible. Personal access tokens are
not permitted for production jobs.

4. SECRET SCANNING AND LEAKS

4.1 Every repository must run gitleaks as a pre-commit hook and in CI, in
    addition to GitHub secret scanning with push protection.
4.2 If a secret is leaked (committed to a repository, pasted into a
    ticket or chat, or exposed in logs), the owner must revoke and rotate
    it within 1 hour of discovery and report it to Security Engineering
    as a security incident. Deleting the commit is not sufficient.

5. ENCRYPTION

5.1 Data in transit: TLS 1.2 or higher is required; TLS 1.0 and 1.1 are
    disabled on all endpoints.
5.2 Data at rest: all production storage is encrypted with
    customer-managed keys (CMK) stored in Key Vault, rotated annually.

6. DATA CLASSIFICATION

  Public        Approved for public release.
  Internal      Default for business data; not for external sharing
                without approval.
  Confidential  Customer data, financial data, PII. Encrypted, access
                logged, shared externally only under contract.
  Restricted    Credentials, payment card data, health data, security
                logs. Never shared externally. Access via
                just-in-time approval only.

7. IDENTITY AND ACCESS

7.1 Multi-factor authentication is mandatory for all human accounts.
7.2 Access is granted to groups, not individuals, and reviewed every
    quarter by the resource owner.
7.3 Two break-glass accounts exist for emergency administrative access.
    Their credentials are split between two sealed envelopes held by the
    CISO and the Head of SRE. Break-glass sign-in is tested quarterly and
    any use triggers an immediate alert to Security Engineering.

8. EXCEPTIONS

Exceptions to these standards must be approved by the CISO, recorded in
the risk register and reviewed at least every 6 months.
